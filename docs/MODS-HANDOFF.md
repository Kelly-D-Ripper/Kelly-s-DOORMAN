# DOORMAN Maps, saved lists and preview candidate

Client 1.3.4, package 1.3.4, local branch `codex/mods-menu`. Audited release candidate. Packages and source are prepared for a GitHub draft; publication and live installation/restart remain separate actions.

DOORMAN's own client now embeds its real doorman.json card: identity, author, feature description, GitHub and complete-package downloads. Version comes from plugin metadata. Artwork is omitted; a future metadata/client/doorman.png will be embedded automatically under that logical name. No loose client preview files, placeholder art, added runtime scan or persisted setting is needed. Its page uses the existing cached GitHub check and manual complete-package installation because protected DOORMAN updates must keep both helpers in sync. The reused server DLL is unchanged.

All ten DOORMAN-owned scroll areas have permanent visible vertical bars with native colours, draggable handles and a reserved gutter: join checklist/report, installed mods/preview/restart reason/status, Maps list/preview/status, saved-list form/picker. Wrapping uses the reduced content width. The IMGUI fallback also forces a vertical bar. Native game server-browser viewport sizing and its own scrollbar remain untouched. This adds no worker, gameplay callback, disk/network activity or persisted setting.

The native Mods menu now has a Maps tab. It lists top-level .nomap files in BepInEx/plugins/NOCustomMaps/maps, plus maps already opened elsewhere by NOCustomMaps. While the tab is open, one nonrecursive OS watcher marks changes for a debounced off-thread metadata scan. Closing the tab/menu, changing scenes or disposing DOORMAN releases it. No map content hashing, terrain loading, duplicate bundle opening, loader rescan, bundle unloading or map file writes are introduced. New, changed and removed files require a restart; details for already loaded files describe the session's build. The initial file stamp is taken when first viewed, so changes before that first view cannot be retrospectively identified. Other loaded map folders are listed but not watched.

NOCustomMaps 1.3.0 is optional. Its inert _opened fields provide identity and registered charts without invoking the blocking Maps getter. Preview requests load only a selected map's TextAsset/Texture2D/Sprite asynchronously. Optional embedded doorman.json must match the existing mapId; invalid or absent data falls back to the map's own metadata/chart. Borrowed bundles/images stay owned by NOCustomMaps. Map credits/notices are displayed. Unsupported loader versions keep filename listing available. Author recipe: docs/MAP-PREVIEWS.md. No .nomap footer, sidecar requirement, automatic map update, map enable/disable or hot reload is added.

Saved lists are managed from a native overlay in Mods. Save snapshots current ticks into a portable JSON in BepInEx/plugins/DOORMAN-Lists; matching names ask before replacement, and deletion preserves a backup. Load plans by stable content/plugin IDs, blocks missing required items and ambiguous inventories, warns on version differences, preserves unlisted client plugins, protects DOORMAN/Blueprinter, validates hard dependencies and calls the existing reload/restart transaction. Unlisted content is excluded. Sharing is a direct file copy, with no downloads or executable paths in the list. Explicit list actions perform bounded disk reads; no watcher or gameplay scan is added. Details: docs/MOD-LISTS.md.

Developers can ship a flat DLL/JSON/image ZIP or embed the same preview into their DLL using two project resource entries. Exact `doorman.json` is read with Cecil without executing plugin code. A single-plugin DLL supplies its own identity/name; ambiguous multi-plugin DLLs require an explicit matching identity. Image resources are read only when the card is selected, with the same PNG/JPEG size/dimension limits as local images. Disabled wrappers retain their preview and their content cards inherit through verified wrapper ownership.

Preview priority: manual custom sidecars, plugin-bound downloaded metadata, embedded DLL previews, then exact NOMNOM fallback. Duplicate identities within a layer remain ambiguous. The short author guide is docs/MOD-PREVIEWS.md. Stable identities and real release tags avoid per-release preview edits.

The ZIP updater installs only one matching plugin DLL and its explicitly bound, plugin-only preview JSON plus referenced PNG/JPEG. Managed previews live in `BepInEx/plugins/DOORMAN-Metadata/<plugin-ID-hash>`. Queue records bind original/payload hashes and backups for every affected file; earlier DLL-only queues remain readable. Restart verification and startup installation reject changed originals, damaged payloads and ambiguous files. Interrupted transactions must reconcile every affected file before completion. Updates without a sidecar clear only the prior plugin-owned managed preview, allowing a new embedded preview to appear. Manual custom files remain untouched. Standalone `.nobp` previews work; automatic `.nobp` replacement remains unsupported and uses the manual release page.

No Aryx/sample previews or artwork are shipped in CLIENT, FULL or SOURCE. Previous packages/artwork remain local historical evidence. Users upgrading an older test package must remove its old `BepInEx/plugins/DOORMAN-Previews/aryx` folder once; extracting a ZIP cannot delete that previously installed folder. No live cleanup is performed by this build.

Database impact: none. No database copy or migration.

Configuration impact: the Maps view is read-only with no new persisted settings or cache files. Existing configs/favourites and normal profiles are preserved. Explicit saved-list actions create/change JSON files and backups under BepInEx/plugins/DOORMAN-Lists; loading uses the existing doorman-mods.json profile transaction after confirmation where needed. Explicit updates add plugin-owned preview files and per-file queue/backup receipts. Existing server-return ticket, release/NOMNOM cache and restart-status behavior remain documented in docs/SERVER-SETUP.md and docs/UPDATES.md. No server settings change. Server DLL/archive remain the exact published 1.0.0 bytes.
