# Setup mods, then join. A revolutionary concept.

Select a server in Multiplayer. The checklist now has **Setup mods** and **Join server**.

1. **Setup mods** checks the server's complete list against installed versions and already downloaded updates. It enables required content and leaves extra packs out. An exact queued update requires a restart, even if no ticks changed.
2. If safe content reload is available, the list refreshes and **Join server** becomes available when the actual game compatibility string matches.
3. If code, Blueprinter or previously unwired content needs a restart, the panel explains this and changes the action to **Proceed**. Clicking it saves this server's selection and exits the game. Closing the panel before exit cancels the pending restart.
4. A short Windows launcher asks the desktop Explorer to create the restart helper and then exits before Nuclear Option quits. The helper verifies it is an Explorer child, so it cannot keep Steam's old game process family running. If preparation fails, the game stays open. The separate status box shows Configuring mods, Waiting for Steam, Starting game and Loading game and mods. It waits for this exact game process to exit, gives Steam at least ten seconds to settle, and waits for its previous app session to end before requesting Nuclear Option. Available Steam state must remain idle for two seconds. It can retry once if no new game appears, with a four-minute launch limit. It never kills the game or Steam. The box does not take focus and closes once the final menu is ready. Closing the box merely hides progress; the restart continues. After startup, DOORMAN waits for the native menu's Loaded state, Blueprinter completion, an active input system and two stable seconds. The first menu flash does not count.
5. DOORMAN opens Multiplayer, finds the same dedicated connection address/port from Steam server details, or its nonzero Steam identity when the endpoint is unavailable, and reopens its native details page. Hosted servers use their Steam lobby ID. Click **Join server**. Password prompts and the game's authentication, build and map checks remain native.

**Auto match mods when joining a server** starts this same setup from the normal Join button. It can continue directly after a successful hot reload. A restart still asks for **Proceed**, and returns to the page without automatically joining.

For vanilla servers, setup excludes Blueprinter and content wrapper plugins for that startup, plus plugins which require those wrappers. Blueprinter 2.0.1 adds its own compatibility suffix even with no active packs. For modded servers, setup enables required wrappers and their hard dependencies. DOORMAN remains enabled. Unrelated client plugins keep your ordinary selection; soft dependencies alone do not cause disabling. Hard dependents which must be disabled are named before Proceed. Your saved ordinary selection stays in `BepInEx/config/doorman-mods.json`. Hot selections restore on return to Main Menu when supported; a restart selection lasts for that game session and the next ordinary launch uses the saved profile.

Setup uses installed files and already queued updates only. It never downloads missing versions. Queued release versions are projected separately from running content; verified replacement hashes are recorded for the next startup. Missing/wrong versions, game-build differences, unknown loader builds and incomplete/hashed server lists give a useful reason. Hashed lists need the optional DOORMAN Server companion. Setup never guesses a list or rewrites a compatibility identifier to force a join. Startup content selection is supported for the inspected Blueprinter 2.0.1 build; unsupported asset reloads use a normal startup instead.

Install the whole CLIENT or FULL archive with the game closed. Required helpers:

- `BepInEx/patchers/KellysDOORMANStartup.dll`
- `BepInEx/DOORMAN/KellysDOORMANRestart.exe`

The return ticket is `BepInEx/config/doorman-server-setup.json`, with a replacement `.bak`. It includes an endpoint, version list, disabled IDs and a SHA-256 inventory. It contains no password. It expires after six hours and is consumed after startup becomes ready, so it cannot return to that page on every launch. If Steam does not relaunch the game, start it normally yourself. If the server disappears or changes, DOORMAN explains the problem instead of joining another server with a similar name.

Loading waits are bounded to five minutes, opening the browser to one minute and finding the server to 90 seconds. These coroutines run only for a saved restart return. Metadata/file hashing runs off Unity's thread. No server behavior, configuration or database change is included.

The native Mods button also attaches after completed initial loading, and browser controls have a one-frame scene-event fallback when Unity's Start hook did not attach them. Both work with Blueprinter absent and avoid duplicate controls. The restart status handoff expires after fifteen minutes; it does not alter the server ticket. `BepInEx/cache/DOORMAN-restart.log` records Steam session state, actual launch attempts and stage timings for diagnosing a slow Steam release versus slow game loading. Optional Steam registry flags and a bounded local log tail are read only while the external helper is running. Unavailable signals use a conservative two-minute retry interval; an exact game already started manually is adopted without another request.

This is a local test candidate. Static checks cannot establish Unity boot, menu rendering, hot reload networking or a successful Steam relaunch. Follow [MODS-TEST.md](MODS-TEST.md) on a disposable client setup before publication.
