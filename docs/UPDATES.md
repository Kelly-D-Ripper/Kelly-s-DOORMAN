# Updating, without excavating your plugins folder

Open **Mods**, choose a mod, and look below its description. DOORMAN shows its installed version and GitHub's latest stable release. Developers can supply a GitHub link in a local or embedded preview; an exact NOMNOM registry match can also supply the repository when no preview exists.

Press **Update to [version]** to download and queue the replacement. Press **Reload mods** or **Restart to finish update**. A native confirmation explains the restart and offers **Restart game** and **Cancel**. After confirmation, DOORMAN verifies the queued files, exits normally and relaunches through Steam. The startup helper replaces the old DLL before plugins load, keeps its existing filename, and retains the previous DLL as a backup. Existing configs, favourites, saves and databases are preserved. No duplicate versioned DLL gets dropped into your plugins folder.

New DLL code and embedded assets need that restart. With no queued updates or code changes, **Reload mods** can still switch supported content loaded at startup. A downloaded version cannot replace code already running in memory. Server **Setup mods** also recognises a queued update matching that server's required version and offers **Proceed** to restart and return to the server page. Join remains blocked until the actual loaded compatibility string matches.

Checks happen only when a mod's page opens. GitHub results are cached for six hours across game launches; repeated cards for the same repository share the result. Requests are asynchronous and serialized. There is no scheduled checking or network polling during flight. Failures wait fifteen minutes before another attempt; GitHub rate limits also pause requests. Downloads happen only after an Update click.

The updater accepts public GitHub release DLLs and ZIPs containing one matching plugin DLL. An embedded preview travels inside its DLL. A ZIP may also include one JSON preview explicitly identifying that plugin and its referenced PNG/JPEG. Only those bound preview files are installed, with hashes and backups, under `BepInEx/plugins/DOORMAN-Metadata`; unrelated files are left alone. Existing manual previews override downloaded ones. Downloads are bounded to 256 MiB, use HTTPS, and verify GitHub's SHA-256 digest when supplied. ZIP paths, sizes and plugin IDs are checked. Packages with dependencies, standalone `.nobp` content, loaders, DOORMAN itself and ambiguous assets use **Release page** for manual installation. Unknown version names get a manual comparison instead of a guessed upgrade. GitHub's latest release can still differ from a particular server's required version.

The release cache is `BepInEx/cache/doorman-releases.json`. Explicit updates are kept in `BepInEx/cache/DOORMAN-updates/<job>/`: `payload.bin`, `plan.json` and, after installation, `previous.bin`. Backups have a `.bin` extension so BepInEx cannot load them. To roll back manually, close the game and copy the relevant `previous.bin` over the target DLL recorded in `plan.json`. Keep the current DLL elsewhere first. Preview transactions also retain `preview.previous.bin` and `image.previous.bin` when replacing or removing managed metadata; their target filenames are recorded in the same plan. Completed jobs are not reinstalled.

If an installed DLL changes after queuing, or the queued download is damaged, startup preserves the installed mod and reports the reason in the BepInEx log. An interrupted atomic replacement is reconciled using its recorded hashes on the next start. The helper skips headless hosts entirely.
